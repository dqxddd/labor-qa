## 一、项目简介

一个基于 RAG（检索增强生成）的劳动权益法规问答系统。

先把劳动法规资料导入知识库，系统把资料切成知识片段并建立检索索引；用户用日常语言提问时，系统先检索出最相关的几段依据，再交给大模型生成回答，**回答里必须标出依据来源**；如果资料库里根本没有相关内容，系统明确拒答，不凭印象编。

技术栈：Python 3.11 + FastAPI + SQLAlchemy + SQLite + Streamlit；检索用 Chroma 向量库 + bge-m3 向量模型（关键词检索自动兜底）

## 二、当前进度

### 已完成

| 模块 | 完成情况 |
|---|---|
| 配置中心 | `backend/core/config.py`，参数统一管理，路径自动推导、目录自动创建 |
| 数据库 | `backend/core/db.py` + 8 张表，照《系统设计文档》第五章建立 |
| 资料入库 | 上传 → 解析（md / txt / PDF / Word）→ 切分（500 字、重叠 80 字）→ 写库 → 建索引 |
| 检索 | **向量检索**（Chroma + bge-m3，余弦相似度）为主，**关键词检索**（字符 bigram + TF-IDF）自动兜底；两条路的分数口径不同，阈值分开配置，取 Top-K |
| 问答 | 检索 → 判分 → 拒答或生成 → 会话、消息、引用记录落库；命中之后若问题涉及法定期限，再多一步「调业务工具算期限」 |
| 多轮追问 | 同一会话最近 N 轮问答带进上下文，N 由前端滑块控制；追问搜不到时用上一轮问句兜底重搜 |
| 对话留存 | 问答区按轮次累积显示，新提问不会顶掉上一轮；新回答生成期间，之前的对话仍留在页面上 |
| 应答风格 | 同一批资料按「劳动者通俗版 / 严谨条款版」两种口吻作答，提问框上方切换；两种风格共用同一套检索、引用、拒答，只换说话方式 |
| 流式输出 | `/api/chat/stream` 走 SSE 逐段推送，前端边收边画；可随时切回同步模式 |
| 模型参数 | 左栏可调 temperature / top-p / max-tokens / 历史轮数，模型锁死的参数自动校正并置灰 |
| 接口 | 资料管理 4 个 + 问答 3 个 + 会话 2 个 |
| 业务工具 | `arbitration_limit`：把法定期限算成具体截止日（仲裁时效 / 追索报酬 / 工伤认定三类）。规则预判触发，模型抽参数，算出结果回填给模型；调用记录写进 `tool_calls` 表 |
| 前端 | 知识库管理、智能问答、检索调试、项目进度 四个页面 + 左栏模型参数面板 + 提问框上方的风格切换器；会话区限高滚动，提问框钉在下方（对话再长也不会把输入框挤出屏幕） |

## 五、配置

把 `.env.example` 复制一份改名为 `.env`，放在项目根目录：

```bash
cp .env.example .env
```

然后按需修改，各项含义：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `LLM_API_KEY` | 空 | **大模型密钥，不填的话问答接口会降级**（只返回检索到的依据，不生成回答） |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容接口地址，换供应商只改这里 |
| `LLM_MODEL` | `deepseek-chat` | 模型名 |
| `LLM_TEMPERATURE` | `0.2` | 采样温度。法规场景要稳，不要调高 |
| `LLM_TOP_P` | `1.0` | 核采样阈值 |
| `LLM_MAX_TOKENS` | `1024` | 单次回答最长生成多少 token |
| `LLM_TIMEOUT` | `60` | 请求超时秒数 |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `500` / `80` | 切分长度与重叠字数 |
| `EMBED_PROVIDER` | `api` | 向量怎么算：`api` 走在线接口（推荐），`local` 走本地模型 |
| `EMBED_MODEL` | `BAAI/bge-m3` | 向量模型名，1024 维、中文效果好、硅基流动上免费 |
| `EMBED_API_KEY` | 空 | **向量接口密钥，不填的话向量检索不可用，会自动退回关键词检索** |
| `EMBED_BASE_URL` | 空 | 向量接口地址（硅基流动填 `https://api.siliconflow.cn/v1`） |
| `TOP_K` | `5` | 每次取相关度最高的几条 |
| `VECTOR_SCORE_THRESHOLD` | `0.55` | **向量检索走拒答的分数线**（余弦相似度口径，实测标定出来的） |
| `SCORE_THRESHOLD` | `0.35` | **关键词检索走拒答的分数线**（覆盖率口径）；两条路口径不同，不能共用 |
| `HISTORY_TURNS` | `8` | 带入上下文的历史轮数 |
| `TOOL_ENABLED` | `true` | **业务工具总开关**。设成 `false` 后问答链路完全不碰工具，跟加工具之前一模一样 —— 用来做对照演示 |

> `.env` 里不要用中文引号，值也不要加引号，键名大小写敏感。

**关于模型锁死参数**：`LLM_TEMPERATURE` / `LLM_TOP_P` / `LLM_MAX_TOKENS` / `HISTORY_TURNS` 这四项
在前端左栏「模型参数」面板上都能实时调，不传就用上面 `.env` 里的值。

但有些模型会把采样参数锁死。实测（2026-09-21）：

| 模型 | temperature | top_p | max_tokens |
|---|---|---|---|
| `kimi-k3` | 只接受 `1`，传 0.6 直接 400 | 只接受 `0.95`，传 0.5 直接 400 | 不受限 |

所以 `backend/core/config.py` 里有一张 `MODEL_LOCKS` 表登记"哪些模型锁了哪些参数"：

- 前端拿到后会把对应滑块**置灰**并写明原因，不让人拖一个拖了也不生效的控件；
- 后端还会再校正一次（`llm.resolve_params()`），万一有人直接调接口传了非法值也不会 400；
- 换成 `deepseek-chat` 这类不受限的模型，滑块自动恢复可调，不用改代码。

## 六、数据库初始化

数据库是 SQLite，文件在 `data/app.db`，**正常启动后端时会自动建表**，一般不需要手动操作。

初始化后会生成 8 张表：

```bash
venv/Scripts/python.exe scripts/db_overview.py
```

## 七、项目启动步骤

需要开**两个终端**，都在项目根目录。

**终端 1 —— 启动后端**

```bash
venv/Scripts/python.exe -m uvicorn backend.main:app --reload
```

看到 `Uvicorn running on http://127.0.0.1:8000` 就算起来了。

**终端 2 —— 启动前端**

```bash
venv/Scripts/python.exe -m streamlit run frontend/app.py
```

浏览器会自动打开 http://localhost:8501 ，左侧有四个功能页面和「模型参数」面板
（历史对话轮数 / temperature / top-p / max-tokens / 流式输出开关）。

> 两个注意点：
> 1. **前端必须从项目根目录启动** —— `.streamlit/config.toml`（主题色、关掉 Deploy 按钮）是从启动目录读的。
> 2. **改了代码要重启对应的进程**。uvicorn 带 `--reload` 会自动重载；
>    Streamlit 改了 `app.py` 可以在页面上点「Rerun」，但改了 `theme.py` 或 `.streamlit/config.toml` 要 `Ctrl+C` 重开。
>    改完 `.env` 也必须重启后端，配置只在启动时读一次。

## 九、接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查，含索引状态 |
| POST | `/api/documents` | 上传资料（multipart），入库并建索引 |
| POST | `/api/documents/import-samples` | 批量导入 `data/knowledge` 示例资料 |
| GET | `/api/documents` | 资料列表 |
| GET | `/api/documents/{id}/chunks` | 查看某份资料的片段 |
| DELETE | `/api/documents/{id}` | 删除资料及其片段、索引 |
| POST | `/api/chat/sync` | 同步问答（检索 + 生成 + 落库），一次返回 |
| POST | `/api/chat/retrieve` | 只检索不生成，含分数与阈值，调参用 |
| POST | `/api/chat/stream` | 流式问答，SSE 逐段推送（`meta` / `delta` / `done` 三类事件） |
| GET | `/api/sessions` | 会话列表 |
| GET | `/api/sessions/{id}/messages` | 某个会话的消息记录 |

`/api/chat/sync` 和 `/api/chat/stream` 收的请求体一样，参数都可选：

```json
{
  "question": "试用期最长能有多久？",
  "session_id": 12,
  "temperature": 0.2,
  "top_p": 0.95,
  "max_tokens": 1024,
  "history_turns": 8,
  "style": "plain"
}
```

后五项不传就用默认值；`temperature` / `top_p` / `max_tokens` 传了会先过一遍
`llm.resolve_params()` 做参数自适应，响应里 `params` 是**实际发给模型的值**，
`param_notes` 说明哪些值被改过、为什么。
`style` 取 `plain`（劳动者通俗版）或 `strict`（严谨条款版），传了不认识的值
会由 `prompts.resolve_style()` 兜回默认，不会报错；响应里带 `style_name` 方便核对。

`/api/chat/stream` 的返回长这样（每行一个 `data:`，`\n\n` 结尾）：

```
data: {"type":"meta","session_id":12,"citations":[...],"params":{...}}

data: {"type":"delta","text":"根据"}

data: {"type":"delta","text":"《劳动合同法》"}

data: {"type":"done","result":{...落库后的完整结果...}}
```

## 十一、已知问题与下一步

1. **检索比的是"意思像不像"，不是"资料里到底有没有写"**。主路已经换成 Chroma + bge-m3 向量检索（余弦相似度），换个说法问（「被开除能赔钱吗」）也能命中 —— 实测同一批问题，向量命中库内 8/8、库外误放行 0/6，而关键词只有 3/8 和 1/6。但它终归是相似度匹配，碰上**语料里根本没写过、只是措辞上沾边**的话题，仍可能搜到片段并作答。拒答靠两道防线一起守：**向量分数阈值 0.55**（`VECTOR_SCORE_THRESHOLD`）+ 提示词里「资料里没依据就直说」的硬规则。
2. **同类词误伤已明显缓解，但没消除**。以前「最低工资是多少」会同时命中试用期那段的「不得低于当地最低工资标准」，排序靠后看不清；换成向量评分后排序准很多，但语料里同时存在多个相近话题时，Top-5 里仍可能混进次要片段。
3. **多轮历史是"全塞进去"，没做摘要**。开了 8 轮就是最近 8 轮问答原样进 prompt（助手回答超过 300 字只留开头），还没做历史摘要压缩，轮数开大以后 prompt 会变长、费用和延迟都会上去。
4. **追问的指代消解只是兜底，而且是靠指代词判断的**。规则是：当前问题自己检索不到、**且问题里带「那 / 这个 / 它」这类指代词**时，才把上一轮问句拼进来重搜一次。没有无条件拼是有原因的 —— 早期版本无条件拼，结果同一会话里问「怎么申请专利」（库外问题）会借上一轮的「加班费怎么算」搜到片段并硬答，把"没依据就拒答"的底线弄丢了。加了判断条件后实测：库外问题照常拒答，「那仲裁时效是多久」这类追问能正确借到上文。局限是碰上「这个怎么处理？」这种既含糊、用词又完全不在语料里的追问，仍然会走到拒答，需要用户换个说法。
5. **模型锁死的参数滑块不可调**。`kimi-k3` 只认 `temperature=1`、`top_p=0.95`，所以这两个滑块在界面上是灰的。这是模型方的硬限制，不是前端没做 —— 换成不受限的模型（改 `.env` 里的 `LLM_MODEL`）会自动恢复可调。
6. **参数没有落库**。这一轮用了什么参数只在响应里返回、显示在右栏，没有写进 `messages` 表，换个页面就看不到了。
7. **扫描件 PDF 和老版 `.doc` 解析不了**。PDF 走的是 `pypdf` 抽文字层，整页是图片的扫描件抠不出文字；Word 只认 `.docx`，老版二进制 `.doc` 需要先用 Word 另存为 `.docx`。这两种情况都会明确提示原因、把资料标成 `failed`，不会静默入库空内容。要支持扫描件得另外接 OCR，不在当前范围内。
8. **对话记录只活在浏览器会话里**。问答区保留的轮次存在前端的 session state 中，刷新页面或重开标签页就清空了 —— 数据库里其实存着这些消息，但前端拿不到自己属于哪个历史会话（会话编号本身也在这个状态里）。
9. **两种应答风格换的是"说法"，不是"依据"**。硬规则（只依据资料、标来源、没依据就拒答、数字照抄）写在 `prompts.STYLE_COMMON` 里由两种风格共用，所以切风格不会动摇拒答底线；但也因此，两种风格引用的资料、检索结果、分数完全一样，差异只在措辞、结构、是否举例上。另外**风格和参数都没有落库**，翻历史消息看不到当时用的是哪种风格。
10. **向量检索依赖在线接口**。bge-m3 走的是在线 API，建索引和查询都要联网。没网、key 失效、余额不足时会**自动降级回关键词检索**，检索接口不会报 500；页面和 `/health` 会如实说明「本轮走了兜底检索 + 原因」，不会假装一切正常。降级时命中率会明显下降，这是设计上的取舍（宁可答得少，也不要整个问答瘫掉）。
11. **首次建索引有冷启动成本**。每段文字都要调一次接口换向量（500 字一段，20 段就是 20 次请求），比关键词建索引慢得多。已经加了本地缓存 `data/vectorstore/embed_cache.json`（同一段文字只算一次向量），重建索引时命中缓存的直接跳过 —— 所以只有第一次导入、或者资料内容真的改了才会慢。换向量模型也要重新算一遍。
12. **会话区高度是靠 CSS `:has()` 改父层的 flex-basis 撑出来的**，属于"绕过 Streamlit 默认行为"的做法：Streamlit 把固定高度写成父层容器上的 `flex-basis`（而不是会话框自己的 `height`），所以只能从父层下手。这需要 Chrome / Edge 105+、Safari 15.4+、Firefox 121+；更老的浏览器会退回 430px 固定高度，那种情况下窗口高度不足约 700px 时提问框要滚动才能看见。
13. **极窄的窗口仍会滚动**。CSS 里给会话区留了 200px 的最小高度，窗口高度低于约 670px 时整页会出现滚动条 —— 这是网页上的正常表现，不影响功能。
14. **业务工具只覆盖三类期限，而且没法脱离资料单独用**。仲裁时效 / 追索报酬 / 工伤认定之外的期限（比如不服仲裁裁决 15 日内起诉、工伤待遇申请）没做。另外工具排在**拒答判断之后** —— 资料库里没相关依据时照样拒答，工具不会执行，这是刻意的设计（宁可不算，也不越过"只依据资料"这条线）。
15. **工具的类别判定是词表匹配，不是语义判断**。规则是"问到时限 + 落到某个话题"两道门槛，换个不常见的说法可能漏判（比如「公司拖着不给钱，我还能告吗」既没有"时效"也没有强词，就不会算期限）。反过来，命中词表但其实不必算的时候也会算一次 —— 后果只是多显示一块信息，不影响回答质量。
16. **模型给的起算日可能有偏差**。日期是从模型填的参数里解析的，它把「去年 3 月」这类相对说法换算错、或者用户压根没说日期时，工具一律返回 `ok=false` 并附上"请先问用户具体日期"，由模型转成一句追问 —— **绝不猜一个日期出来**。猜错日期的代价比不答大得多。
17. **命中期限规则的问题会多花一次模型调用**。这类问题要发两次请求（先抽参数、再生成回答），延迟多一两秒、token 费用翻倍；没命中的问题不受影响。
